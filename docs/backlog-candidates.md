# 추가 백로그 후보 (논의용)

현재 백로그 1~22번은 응시·감독·재생·리포트까지 한 사이클을 모두 덮고 있음. 아래는 (a) 명백한 갭 메꾸기, (b) 운영 강건성 두 갈래로 정리한 후보안.

## 기능적 후보

| 후보 | 메인 메뉴 | 핵심 시나리오 | 갭/근거 |
|---|---|---|---|
| A. 학생 결과 조회 | 응시 | 종료 후 학생이 본인 점수/답안을 확인 (교수의 공개 여부 토글 포함) | 현재 학생은 제출 후 끝 — 결과를 다시 보는 경로 없음 |
| B. 시험·명단 수정 | 교수 대시보드 | 시작 전 한정으로 문항/시각/응시자 명단 편집 | 4·5번 개설 후 오타 하나 못 고침 |
| C. 감독관 → 학생 경고 푸시 | 감독관 | 학생 상세 패널에서 경고 메시지를 전송, 학생 화면 상단에 표시 | 17·18에서 의심 신호만 보고 끝 — 개입 수단 없음 |
| D. 감독관 강제 종료 | 감독관 | 학생 상세 패널에서 시험을 강제 종료, 학생은 그 시점까지의 답안으로 제출 처리 | C의 강한 버전, 둘 중 택1 가능 |
| E. 개별 시간 연장 | 교수 대시보드 | 시작 직전/도중에 특정 학생의 종료 시각만 N분 연장 | 21번(자동 제출)과 짝, 지각·장애학생 대응 |
| H. 좌석 배치도 감독 | 감독관 | 교수가 강의실 배치를 n×m으로 지정하면 응시자를 좌석에 자동 배치, 감독관 대시보드를 좌석 배치도 뷰로 모니터링 | 현재 학생 목록은 리스트뷰뿐 — 실제 강의실 좌석과 매핑되는 공간 인지 수단 없음 |

## 비기능적 후보

| 후보 | 카테고리 | 핵심 시나리오 |
|---|---|---|
| F. 동시 응시 부하 검증 | 시스템 | 100명 동시 응시 시 감독관 대시보드가 1초 이내로 갱신되며 이벤트 손실 0건 |
| G. 네트워크 단절 복구 | 응시 | 응시 중 WiFi 끊김 → 재연결 안내 + 답안/이벤트 클라이언트 큐 보관 → 네트워크 복구 즉시 자동 재연결(응시 화면 유지 시 재입장 불필요) + 큐 일괄 재전송 + 답안 보존 |
| I. 교수 메인 대시보드 UI 리팩토링 | 품질/UX | 교수 메인 대시보드 정보 구조·레이아웃 재설계 (시험 목록/상태/빠른 액션 동선 정리) |

## 추천 조합

- C와 D는 결이 비슷하므로 둘 중 하나만 채택해도 충분
- **A + B + C + F + G** 5개가 균형 좋은 후보 (기능 3 + 비기능 2)
- 우선순위 정해지면 백로그 23번부터 데모 시나리오 형식으로 정리 예정

## 논의 포인트

1. C vs D: 경고 푸시(부드러운 개입) / 강제 종료(강한 개입) 중 어디까지 갈지
2. B의 범위: 시작 전만 허용할지, 시작 후에도 일부 항목(시각만)은 허용할지
3. F의 부하 기준: 100명이 적절한지, 실제 데모 환경에서 어디까지 보장할지
4. E의 권한: 교수만 가능한지, 감독관에게도 부여할지

## 데모 시나리오 (제안)

번호는 잠정. 채택되는 후보만 백로그 23번부터 순서대로 옮길 예정.

| Backlog NO. | 메인 메뉴 | Sub-1 메뉴 | Demo Scenario |
|---|---|---|---|
| A | 응시 | 학생 결과 조회 | 1. 시험이 종료된 후 학생이 결과 조회 페이지 URL에 접속한다.<br>2. 시험 코드, 학번, 이름을 입력하고 '결과 보기' 버튼을 클릭한다.<br>3. 교수가 '결과 공개'를 활성화한 시험이면 본인의 총점, 객관식 자동 채점 결과, 주관식 채점 점수와 코멘트가 문항별로 표시된다.<br>4. 결과가 비공개로 설정된 시험이면 "아직 결과가 공개되지 않았습니다" 안내가 표시된다.<br>5. 교수는 시험 상세 페이지에서 '결과 공개' 토글을 켜거나 끌 수 있다.<br>6. 교수가 토글을 끄면 이미 결과를 본 학생도 즉시 비공개 안내 화면으로 전환된다. |
| B | 교수 대시보드 | 시험·명단 수정 | 1. 교수가 시험 상세 페이지에서 '시험 수정' 버튼을 클릭한다.<br>2. 시험이 아직 시작되지 않았으면 시험 수정 페이지로 이동한다.<br>3. 시험명, 시작/종료 시각, 문항(본문/배점/정답/이미지), 응시자 명단을 자유롭게 수정할 수 있다.<br>4. '저장' 버튼을 클릭하면 변경 내용이 반영되고 시험 상세 페이지로 돌아간다.<br>5. 시험이 이미 시작된 경우 '시험 수정' 버튼은 비활성화되며 "이미 진행 중인 시험은 수정할 수 없습니다" 툴팁이 표시된다.<br>6. 단, 시험 진행 중에도 '종료 시각'만 별도로 연장하는 버튼은 활성화되어 있다. |
| C | 감독관 | 학생 경고 푸시 | 1. 감독관 대시보드의 학생 카드를 클릭하여 상세 패널을 연다.<br>2. 상세 패널의 '경고 보내기' 버튼을 클릭한다.<br>3. 경고 메시지 입력란에 텍스트를 입력하고 '전송' 버튼을 클릭한다.<br>4. 학생 응시 화면 상단에 경고 메시지가 빨간색 배너로 표시된다.<br>5. 학생이 배너의 '확인' 버튼을 클릭하면 배너가 사라지고 확인 시각이 감독관 패널에 기록된다.<br>6. 학생이 일정 시간(예: 30초) 내에 확인하지 않으면 감독관 패널에 '미확인' 상태로 표시된다.<br>7. 전송된 경고 기록은 학생 상세 패널에 시간순으로 누적 표시된다. |
| D | 감독관 | 강제 종료 | 1. 감독관 대시보드의 학생 카드를 클릭하여 상세 패널을 연다.<br>2. 상세 패널의 '시험 강제 종료' 버튼을 클릭한다.<br>3. 확인 다이얼로그에서 종료 사유를 메모로 입력한다.<br>4. '확인' 버튼 클릭 시 해당 학생의 응시 화면이 즉시 종료된다.<br>5. 학생이 그 시점까지 작성한 답안이 자동 제출 처리된다.<br>6. 학생 화면에는 "감독관에 의해 시험이 종료되었습니다" 안내와 사유가 표시된다.<br>7. 종료 기록과 메모는 사후 리포트(20번)에 표시된다. |
| E | 교수 대시보드 | 개별 시간 연장 | 1. 교수가 시험 상세 페이지의 응시자 명단에서 학생 한 명의 행을 클릭한다.<br>2. '시간 연장' 버튼을 클릭한다.<br>3. 다이얼로그에서 연장할 시간(분 단위)을 입력하고 '저장' 버튼을 클릭한다.<br>4. 해당 학생의 시험 종료 시각만 N분 연장된다.<br>5. 학생 응시 화면의 남은 시간 표시가 자동으로 갱신된다.<br>6. 다른 학생의 종료 시각은 변경되지 않는다.<br>7. 연장 기록(연장 시각, 연장 시간, 처리자)이 학생 행에 누적 표시된다. |
| F | 시스템 | 동시 응시 부하 검증 | 1. 부하 테스트 환경에서 100명의 가상 학생이 동일 시험에 동시에 응시를 시작한다.<br>2. 각 가상 학생이 5초 간격으로 답안 작성, 문항 이동, 화면 이탈, 붙여넣기 등 다양한 이벤트를 발생시킨다.<br>3. 감독관 대시보드가 모든 이벤트를 1초 이내에 갱신한다.<br>4. 30분 응시 동안 서버에 도달한 이벤트 손실이 0건임을 로그로 확인한다.<br>5. 답안 제출 시점에 100명의 답안과 스냅샷이 모두 정상적으로 저장된다.<br>6. 부하 시험 종료 후 사후 리포트(20번)가 정상적으로 생성된다. |
| G | 응시 | 네트워크 단절 복구 | 1. 학생이 응시 중인 상태에서 네트워크 연결이 일시적으로 단절된다.<br>2. 학생 화면 상단에 "연결이 끊어졌습니다. 재연결 중..." 안내가 표시된다.<br>3. 단절 동안 학생이 작성한 답안과 발생한 이벤트는 클라이언트에 큐로 보관된다.<br>4. 학생은 단절 동안에도 답안 작성과 문항 이동을 계속할 수 있다.<br>5. 네트워크가 복구되면 즉시 자동으로 재연결된다 (응시 화면이 열려 있는 한 별도 재입장 없이 바로 이어짐).<br>6. 큐에 보관된 답안과 이벤트가 서버로 일괄 재전송된다.<br>7. 감독관 대시보드에 단절/복구 구간이 별도 마커로 표시되고 데이터가 누락 없이 이어진다.<br>8. 단절이 시험 종료 시각까지 복구되지 않은 경우, 21번(시간 만료 자동 제출)의 답안 스냅샷 기반 처리가 적용된다. |
| H | 감독관 | 좌석 배치도 감독 | 1. 교수가 시험 설정에서 강의실 좌석 배치를 행 x 열(n×m)로 지정한다.<br>2. 지정한 그리드에 맞춰 응시자 명단의 학생들이 좌석에 자동 배치된다.<br>3. 감독관 대시보드가 리스트 뷰 대신 좌석 배치도 뷰로 학생 카드를 격자 배열한다.<br>4. 각 좌석 카드에 학생의 실시간 상태(응시중/이탈/의심 신호)가 색상으로 표시된다.<br>5. 감독관이 특정 좌석 카드를 클릭하면 해당 학생 상세 패널이 열린다.<br>6. 빈 좌석과 미배치 학생은 별도로 구분 표시된다.<br>7. 교수가 좌석 위 학생을 드래그하여 배치를 수동으로 조정할 수 있다. |
| I | 교수 대시보드 | 메인 대시보드 UI 리팩토링 | 1. 교수 메인 대시보드의 정보 구조를 재설계한다(진행 예정/진행 중/종료 시험 구분).<br>2. 시험 카드에 상태 배지와 핵심 지표(응시자 수, 시작·종료 시각)를 일관된 레이아웃으로 표시한다.<br>3. 자주 쓰는 액션(시험 개설, 상세 보기, 감독 진입)을 명확한 동선으로 배치한다.<br>4. 반응형 레이아웃으로 다양한 화면 폭에서 깨지지 않게 정리한다.<br>5. 기존 기능·라우팅은 그대로 유지한 채 표현 계층만 개선한다. |
